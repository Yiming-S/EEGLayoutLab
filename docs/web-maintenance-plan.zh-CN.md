# 网页端维护与服务器交付方案

EEGLayoutLab 现在以网页端为唯一维护产品。Mac 原生外壳、打包工具和专用测试已经移除；macOS 上仍可通过浏览器使用现有科学运行环境。

本轮重构已在本机完成公共接口、任务执行、存储入口、功能页面和三维查看器的拆分，并加入部署配置、维护模式及备份恢复工具。各阶段的具体测试与证据见[重构记录](web-refactor-progress.zh-CN.md)，服务器平台、运行环境和访问配置的验收步骤见[部署说明](server-deployment.md)。

## 已完成的模块边界

| 位置 | 职责 |
| --- | --- |
| `contracts/` | 布局类型、现有接口格式说明、Node/Python 共用请求样例 |
| `webapp/app/` | 路由入口和功能组合 |
| `webapp/features/` | 概览、布局设计、电极编辑、比较、信号仿真、记录库和历史结果 |
| `webapp/client/` | 统一任务请求、轮询、连接状态和恢复 |
| `webapp/viewer/` | 模型加载、资源释放、电极与源标记图层、相机和交互 |
| `webapp/server/http/`、`host/` | HTTP 响应、访问策略、框架启动、配置和本地运维信号 |
| `webapp/server/jobs/` | 唯一执行许可和 Python 进程生命周期 |
| `webapp/server/runtime/`、`storage/` | 科学身份、解释器和路径选择、现有记录读写 |
| `src/compact_eeg/` | 科学计算核心与工作流 |

浏览器代码不能导入服务端实现；服务端不能形成循环依赖。这些规则由自动检查执行。公共类型不再依赖三维场景。接口样例直接检验现有 Node 和 Python 验证器，目前没有引入自动生成接口类型的工具链。

信号结果页将数据投影、播放状态和双侧接收视图分开。两侧继续共用同一时间位置、波形尺度和电位色标。三维模块分别管理资产、图层及资源生命周期；加载或初始化失败会释放已取得的资源。科学坐标、分区标签、指标和计算协议保持原有含义。

双侧查看器共享按 SHA-256 验证的模型字节，各自保留独立几何数据。随后已完成三个阶段的加速：复用原生前向计算准备与精确结果、按文件变化复用环境检查、无损压缩并延后屏幕外三维加载。隐藏页面时暂停播放计时器。各阶段分别测试，并对照原版科学结果；耗时、数值一致性和首次计算的额外开销见[优化验收记录](performance-optimization-progress.zh-CN.md)。

## 已完成的执行与兼容规则

四类计算共用一个执行许可。后台统一处理输出、进度、取消、超时和进程退出；结果验证及持久化结束后才释放许可。缓存命中不占用计算许可。网页连接失败与后台任务失败分别显示，恢复连接后继续查询原任务。

请求规范化、已有路由和科学缓存身份保持兼容。JSON 响应增加 `X-EEG-API-Version: 1`，错误保留 `error` 并附加稳定的粗粒度 `code`。旧命令入口和兼容导出保留。科学协议变更、旧记录读取和当前缓存命中分别验收，不通过改写旧哈希或放宽坐标匹配获得命中。

## 路径与数据保留

网页宿主使用当前代码目录中的 `webapp/` 和构建产物。`EEG_REPOSITORY_ROOT` 指定实际用于计算的科学目录，包含 Python 源码、科学配置、模型输入、结果和运行环境；默认与网页代码目录相同。`EEG_QUEUE_DIRECTORY` 可单独指定绝对路径保存队列。

这允许新版网页宿主使用一个明确的科学快照。科学目录内部仍沿用现有相对路径，包括 `results/v2/` 下的冻结输入和生成记录。本轮没有拆成任意独立的模型目录与结果目录，也没有启动时静默迁移。发布清单检查网页版本要求的科学源码与所选科学目录是否一致，并分别记录源码、数据和运行环境身份。

`EEG_COMPUTE_PYTHON` 选择普通工作进程的解释器；原生服务仍优先使用科学目录内已有的托管环境。路径变化也会影响部分缓存身份，恢复后必须实际检查。

## 维护、备份和回退

生产服务始终监听 `127.0.0.1`。`SIGUSR2` 开启持久化维护模式，停止接受新的未缓存计算，也停止派发排队任务。缓存读取、取消及已完成任务的状态同步继续工作。健康接口的 `drained: true` 表示没有正在执行或状态不明的计算；待执行任务保留顺序。

确认排空后停止旧服务，再执行备份。维护模式下仍可能写入读取回执，因此排空不能替代停机。重启后暂停状态保留，由 `SIGUSR1` 明确恢复；浏览器令牌不能开启或关闭维护。

`release_manifest.py` 和 `backup_service.py` 默认只预览，添加 `--execute` 才写入新的项目 `artifacts/` 路径。备份包含源码、生成记录、队列和签名密钥；模型数据包、依赖环境、构建产物和私有环境配置分别保留。恢复校验完整清单和哈希，只创建新目录，不覆盖现有安装。恢复完成仍需安装数据与依赖、构建并验收。准确命令见[运维指南](web-operations.md)。

## 分层验证

| 层级 | 已建立的流程 | 运行条件 |
| --- | --- | --- |
| 快速检查 | 类型、静态规则、公共格式样例、模拟任务与科学单元测试、网页构建 | 无外部科学数据包的源码副本 |
| 数据集成 | 固定数据校验、真实 HTTP 计算、记录读写与缓存回放 | 独立数据工作区 |
| 原生计算 | 原生坐标计算、单源与多源请求、来源和缓存检查 | 合格的 SimNIBS 环境与模型 |
| 浏览器 | 三维显示、页面和关键操作、中英文、下载 | 已启动服务与浏览器 |

快速检查工作流已写入 `.github/workflows/checks.yml`，并在本地无科学数据副本上执行；尚未在远程 GitHub Actions 运行。缺少数据或原生环境的项目明确跳过或排除。完整测试不能由快速层代替。使用[贡献指南](../CONTRIBUTING.md)中的隔离工作区工具，不能把不同端口当作不同数据目录。

## 服务器尚待完成的工作

1. 确认操作系统、CPU 架构、资源容量和安装权限，建立并验证该平台的科学环境。现有托管环境针对 Apple Silicon macOS。
2. 确定谁能提交计算、结果是否共享以及保留期限。当前为匿名签名会话和共享科学结果库。
3. 配置独立子域名、HTTPS、反向代理与进程管理。公开来源和受信代理策略已实现并通过本地测试；真实网址尚未验收。
4. 在目标服务器运行代表性未缓存计算，检查精确缓存回放、取消、重启和历史记录读取。
5. 演练停机备份、新目录恢复、升级与回退，记录运维联系人和公开地址。

代理必须覆盖公共 `Host`、`X-Forwarded-Proto: https` 和单一真实客户端 IP，不能透传来访者自带的转发头。默认配置不信任这些头。配置模板和部署边界见[服务器部署说明](server-deployment.md)。

后续升级按功能或依赖组分开处理。界面升级不得改变科学含义；科学变更必须明确输入、协议和回归依据。主机部署由服务器维护者负责，接口、科学协议和发布验证由项目维护者与服务器维护者共同确认。
