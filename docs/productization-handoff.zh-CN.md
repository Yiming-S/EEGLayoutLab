# EEGLayoutLab 部署准备与验收说明

本文说明服务器部署所需的源码、版本材料、安装条件、检查工具和恢复步骤。目标服务器的系统、CPU 架构、资源容量和公开地址尚未确定，真实服务器验收仍待执行。本地分阶段结果见[产品化记录](productization-progress.zh-CN.md)。

本轮四个本地阶段已通过验收，覆盖长期项目、研究流程、统一交付与运维工具。最终生产构建、442 项网页测试、460 项 Python 测试、浏览器工作流和四阶段科学对照通过；实际文件恢复与项目读取已演练。验收材料存于源码目录的 `artifacts/productization/2026-11-13/`，其中包含私有备份及项目访问材料，不随公开源码或 Releases 分发。

## 交付范围

- 网页应用、Node 服务和 Python/SimNIBS 科学工作流。
- 长期项目记录、项目研究要求、布局/编辑/信号结果的完整存档。
- 跨浏览器手动恢复项目凭据、可撤销的只读分享。
- 包含原始快照文本、校验值、研究元数据和版本引用的统一科学交付包。
- 请求编号、任务关联、运行状态、资源检查及只读本机探针。
- 维护、排空、停机备份、新目录恢复和版本回退的操作说明。

项目负责人名称是研究元数据，不是实名账号。首版通过项目编号和访问凭据管理权限，没有研究者账号、邮箱登录或自动找回密码。计算提交仍使用现有匿名签名会话；原始布局库仍由服务器共享。项目私有存档不会改变原布局库的访问范围。

## 必须分别保存的材料

| 材料 | 用途与保存方式 |
| --- | --- |
| 源码版本、依赖锁文件、生产构建 | 确定运行的软件；完整执行 `npm ci` 和 `npm run build` |
| 发布清单 | 记录源码、模型数据与实际科学环境身份；独立保存清单校验值 |
| 基础模型数据包及 SHA-256 | 按 `data/manifest.json` 安装和校验；不以历史计算缓存替代输入数据 |
| 目标平台科学环境及安装记录 | 安装并验证该平台的 Python、SimNIBS 和原生求解依赖 |
| 私有环境文件与代理配置 | 放在仓库外，限制读取权限 |
| 停机备份 | 包含科学记录、队列、签名密钥及完整 `projects/` 私有档案 |
| 项目访问文件 | 由持有者私下保留；服务器凭据哈希不能还原明文访问密钥 |
| 运维日志与验收报告 | 按保留规则单独保存；请求日志不属于科学结果备份 |

已提供的科学运行环境针对 Apple Silicon macOS。Linux 或其他架构需要独立安装和资格验证，不能直接复制 macOS 环境作为可执行部署。当前 Node 要求为 22.13.0 或更新版本；具体候选版本和锁文件仍须在目标平台验证。

## 服务器启动准备

1. 确认系统、架构、CPU、内存、持久化磁盘、安装权限和运行账号。
2. 按[源码安装说明](source-installation.md)安装代码、数据与合格科学环境。运行数据校验和环境检查，确认实际选中的普通与原生 Python 路径。
3. 在 `webapp/` 执行 `npm ci`、类型和静态检查、适用测试及 `npm run build`。完整构建包含静态模型压缩副本，不能只执行框架构建命令。
4. 从[环境模板](../configs/deploy/server.env.example)生成仓库外的私有配置。分别确认网页代码目录、科学目录和队列目录。每个队列只能由一个服务持有。
5. 首次以维护模式启动，在直接本机地址检查状态。公网开放前，在隔离验收目录验证真实新计算和恢复流程。

从网页源码所属仓库根目录启动：

```sh
node --env-file=/absolute/path/server.env webapp/server/start.mjs
```

私有配置模板默认使用：

| 设置 | 默认值 | 含义 |
| --- | ---: | --- |
| `EEG_MAINTENANCE` | `1` | 启动保持暂停；由操作系统信号明确恢复 |
| `EEG_MIN_FREE_DISK_MB` | `512` | 科学与队列文件系统的最低剩余空间，单位 MiB |
| `EEG_MAX_HOST_RSS_MB` | `0` | 关闭当前 Node 内存阈值；非零时仅用于新工作的准入判断 |
| `EEG_OPERATIONS_LOG_MB` | `5` | 每个 UTC 日请求日志上限，单位 MiB；保留七天 |

磁盘和内存检查失败时，新工作暂缓，已有结果读取、精确缓存回放和取消继续可用。Node 当前内存不等于科学工作进程峰值；这套检查也不是操作系统硬内存上限。应实测新计算耗时、工作进程峰值内存、排队时间和存储增长，再决定服务器容量和资源配置。

[Linux systemd 模板](../configs/deploy/eeglayoutlab.service.example)仅供具备该平台条件时使用，尚未安装或启用。必须替换运行账号、Node 路径、源码目录和私有配置路径；在真实平台验证后再纳入进程管理。

## 只读本机检查

```sh
node webapp/scripts/probe-service.mjs \
  --url http://127.0.0.1:3000 --allow-paused \
  --output artifacts/deployment/candidate-probe.json
```

探针只读取 `/api/operations/status`，不提交计算、不取消任务、不修改维护状态，也不需要网页或项目凭据。它使用原始 HTTP；浏览器请求和带代理转发头的请求会被拒绝。公开代理必须封锁这个运维路径。

- 返回 `0`：就绪；加 `--allow-paused` 时，也接受暂停且已排空的验收状态。
- 返回 `2`：服务能回应，但尚未就绪，或存在资源、日志告警。
- 返回 `3`：连接、超时、HTTP 或响应格式检查失败。
- 返回 `4`：命令参数或输出路径错误。

正常运行检查时去掉 `--allow-paused`。探针不能代替科学计算、HTTPS 或浏览器验收。输出文件只允许位于本项目 `artifacts/` 下。

## 目标服务器验收清单

以下项目需要保留版本、运行条件和结果，不以本地通过记录代替：

- [ ] 在目标平台校验每个模型输入、运行环境与实际解释器。
- [ ] 在隔离工作区运行快速、数据、原生计算及浏览器测试；完成代表性的未缓存原生布局和单源/多源计算，与科学基准对照。
- [ ] 相同输入精确回放；元数据改名和项目研究要求变动不修改原科学结果或伪装成重新计算。
- [ ] 计算期间刷新、断线、重连、取消、服务重启，核对任务归属和结果状态。
- [ ] 在实际 HTTPS 地址完成中英文布局、编辑、对比、信号、项目存档和统一交付；验证真实后台暂停与恢复行为。
- [ ] 两个独立浏览器分别提交任务，不能取消另一浏览器的任务；检查限流和排队行为。
- [ ] 在另一浏览器手动恢复项目；只读凭据可读不可改，撤销后不能继续读取；明确原布局库仍共享。
- [ ] 核对可信代理覆盖 Host、HTTPS 和单一真实客户端 IP；Secure-cookie 和公开来源规则符合配置。
- [ ] 核对低磁盘、资源探针失败和可选 Node 内存阈值的拒绝行为，已有结果和取消仍能使用。
- [ ] 通过请求编号定位 HTTP 请求及关联任务；验证日志大小、保留和丢弃告警。
- [ ] 暂停、排空、停止服务，完成备份及新目录恢复，再运行代表性工作流。
- [ ] 演练候选版本失败后的回退，保存实际公开地址、版本清单和运维联系人。

## 停机备份和回退

先对启动日志中的准确 Node 进程发送 `SIGUSR2`，等待本机状态显示 `maintenance: true`、`drained: true`；再停止服务并确认进程和写入已结束。随后按[运维指南](web-operations.md)预览备份，检查清单后用 `--execute` 写入新备份目录。

备份包含私有项目与完整快照；匹配的数据包、依赖环境、构建产物、私有配置和明文项目访问文件分别保留。恢复只创建新目录，不覆盖当前安装。恢复目录仍需要补齐模型数据和合格运行环境、安装依赖、构建并验收，之后才能明确恢复计算。

升级前保存旧版本与兼容的备份。验收失败时停止候选服务，再使用旧代码及对应数据/队列/项目快照恢复。代码回退不能自动撤销不兼容的数据变更。

- 新版本更新、故障处理和恢复的实际负责人。
