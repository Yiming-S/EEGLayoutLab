# 三阶段性能优化验收

2026-11-13 完成三项优化，按共享前向计算、运行环境检查、传输与页面加载的顺序逐项验证。测试使用独立科学目录 `artifacts/verification/phase2-isolated/`，未向日常结果库写入测试任务。原始报告、数值对照、脚本和截图集中保存在 `artifacts/performance-optimizations/2026-11-13/`，这些本地材料不进入源码仓库。

## 1. 布局评价与信号仿真共享前向计算

原生坐标布局完成评价时，复用同一个模型实例、源算子和矩阵分解，为后续信号仿真准备精确前向场。缓存保存在 `results/v2/reception_forward/shared_fields/`，包含矩阵、质量检查和完整身份。信号页仍验证布局已完成评价，不能用未完成任务或近似坐标命中。

这项优化保留两条原有坐标投影路径。重复投影实测会使坐标产生最大约 `1.42e-14 mm` 的浮点变化；直接把布局评价矩阵当作信号矩阵，会改变部分数值。因此现在共享耗时的准备过程，必要时执行第二次精确场计算，再保存原信号流程应得到的矩阵。

| 真实 HTTP 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 新坐标布局评价 | 103.602 秒 | 128.199 秒 |
| 随后的单源信号仿真 | 106.119 秒 | 4.253 秒 |
| 上述两步合计 | 209.721 秒 | 132.452 秒 |

整套流程本次减少 36.8%。代价是首次布局评价增加约 25 秒；只做布局评价而不运行信号仿真的用户不会获得这部分收益。表中每步包含 HTTP 轮询、结果验证和一次相同请求的缓存回放，来自同一隔离环境中的前后验收记录，不是纯求解器耗时或多轮统计。

缓存采用完整输入与运行环境身份、数组校验和及原子发布。代码、模型、坐标或线程配置变化会产生新身份。可选的信号准备失败时仍返回原本成功的布局评价；身份变化、损坏缓存及取消不会被当作成功处理。旧信号缓存格式继续读取，备份工具包含新增缓存目录。

本阶段完成原生计算、单源与多源仿真、缓存回放、失败/中断路径和完整数值对照。真实 HTTP 检查覆盖 11 个页面、402 条已有记录及 8 条计算路径。证据：`stage1-acceptance.json`、`scientific-stage1/summary.json`，修改前计时位于 `artifacts/web-refactor/2026-11-13/phase2-live.log`。

## 2. 按文件变化复用运行环境身份

第一次仍运行完整 Python 环境检查。后续请求核对实际文件状态；文件、目录、导入位置、解释器、启动器、符号链接及目标发生变化时重新检查。观察项包含设备与 inode、文件类型、大小、纳秒修改/变更时间和执行权限，并合并同时到来的检查请求。旧科学快照缺少新检查脚本时，继续执行原来的完整检查。

| 测量项 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次身份准备 | 787 毫秒 | 1,247 毫秒 |
| 随后四次身份准备 | 386–401 毫秒 | 32–36 毫秒 |
| 五次请求启动 Python 检查的次数 | 5 | 1 |

首次额外开销用于建立文件观察记录。上表只计算身份准备，结果读取和验证仍约 45 毫秒，不能把 32–36 毫秒写成完整 HTTP 响应时间。

前后完整身份对象、运行环境 SHA-256、科学缓存键和返回结果严格相同。回归覆盖新增、删除、替换、权限变化、链接目标出现、路径中链接与 `..` 的组合以及兼容入口变化。证据：`stage2-acceptance.json`、`stage2-runtime-before.json`、`stage2-runtime-after.json`。

## 3. 无损压缩与按需加载

API 使用异步 Brotli/gzip 流压缩 JSON。构建阶段为静态模型生成有体积收益的压缩副本，原模型不变。信号页三维模块接近视口 200 px 时才加载；离开视口后保留相机和通道状态。浏览器页面隐藏时清除播放计时器，返回时从原位置继续；用户主动暂停的播放不会自动开始。

实际 HTTP 验收测得：

| 响应正文 | 未压缩 | Brotli | 减少 |
| --- | ---: | ---: | ---: |
| 信号结果 JSON | 3,879,681 字节 | 1,195,939 字节 | 69.2% |
| 信号页皮层模型 | 12,042,756 字节 | 8,176,125 字节 | 32.1% |

30 项原始 HTTP 检查全部通过：模型解压后的 SHA-256 与原文件一致，返回的完整科学结果与保存对象严格相同；编码协商、HEAD、304、Range、416、缓存控制、接口版本及 CSRF 检查保持有效。没有提交计算任务。首次报告为 `stage3-http-compression.json`，修复下述中断问题后再次验证的报告为 `stage3-http-compression-final.json`。

### 浏览器前后对照

使用同一个已缓存单源结果、英文界面、1440 × 1100 视口、Chrome 软件渲染、10 Mbps 带宽和 40 ms 延迟，每种操作前后各测一次。

| 操作 | 原模型传输量 | 新模型传输量 | 原双视图可用时间 | 新双视图可用时间 |
| --- | ---: | ---: | ---: | ---: |
| 首次加载 | 13.66 MB | 9.72 MB | 20.47 秒 | 16.29 秒 |
| 同页关闭后再打开 | 1.2 kB | 1.2 kB | 4.52 秒 | 4.51 秒 |
| 普通刷新 | 12.04 MB | 8.18 MB | 16.38 秒 | 11.35 秒 |

模型传输量取 Resource Timing 的 `transferSize`，包含响应头；MB、kB 使用十进制单位。可用时间从导航或展开开始，直到两侧可见画布绘制完整模型及 64 个电位值，包含结果查询、脚本加载和渲染。首次加载减少 20.4%，刷新减少 30.7%；同页重新打开的耗时基本不变。

页面未滚动到模型附近时，二进制模型请求为零；同页重新打开也不重新请求二进制模型。两侧独立通道选择、共用色标、实际布局身份及结果回放通过，页面错误和新计算提交均为零。证据：`browser-before-stage3/report.json`、`browser-after-stage3/report.json`、`stage3-browser-comparison.json`。

## 科学结果如何验证

改动前保存原版源代码、请求、完整前向场、布局结果，以及单源/多源信号结果。每个阶段完成后使用相同模型、运行环境、随机种子和线程配置进行比较：

- 原生设计的 `128 × 4352` 前向矩阵逐字节一致；电极坐标、布局指标和计算参数严格相等。
- 单源、多源各 12 个前向输入数组逐字节一致，最大绝对差为 0。
- 三阶段的完整科学结果 JSON 规范化后逐字节一致。仅排除来源说明 `provenance` 和耗时 `elapsed_seconds`；没有删除科学输出字段或放宽数值容差。
- 质量检查仅排除计时字段，求解残差、线程设置、源检查及参考重现结果保持相同。
- 科学求解器、指标公式、配置和模型文件字节未变；改动集中在工作流复用、环境检查和传输/显示层。

第一阶段实际创建一个模型实例并执行两次精确场计算，后续信号仿真不再启动原生求解。第二、三阶段分别再次读取共享前向场并运行单源、多源科学流程，与原版基线比较。汇总见 `scientific-parity-summary.json`，源码与模型核对见 `source-and-model-verification.json`。

## 验证与部署

最终生产构建、类型检查、静态检查通过；Node 测试 361 项通过，Python 测试 457 项及 190 个子测试通过。另有 3 项跳过、2 项原生单元测试排除；原生端到端计算由第一阶段真实运行和独立数值对照覆盖。

三维浏览器回归 20 项通过，覆盖视图、图层、旋转、全屏、手机布局和触摸。完整操作流程 10 项通过，覆盖中英文导航、参数保留、布局与电极编辑、缓存回放、断网恢复、信号播放与通道切换、原始 JSON 下载和任务取消。页面运行错误为零；断网测试只产生预期的网络错误。报告分别为 `viewer/report.json` 和 `workflows/report.json`。

后台暂停、恢复及用户主动暂停的状态逻辑已通过单元测试。额外的真实浏览器补测未完成：切换标签、最小化窗口及关闭自动化焦点模拟后，本机自动化 Chrome 仍直接返回 `document.hidden: false`，未进入隐藏状态。因此不能据此报告真实后台播放已验收；证据保留在 `workflows/visibility-report.json`，需要在能进入隐藏状态的浏览器中补测。

浏览器完整流程回归还发现并修复了压缩响应的中断问题：导航取消请求后，异步读取仍返回结果，向已关闭连接启动压缩会同步抛错，随后错误响应再次写头导致服务退出。现在在写头前检查连接状态，已开始的响应不能被第二份 JSON 替换。新增两项实际 HTTP 测试，修复前都失败、修复后都通过，随后重跑全部 Node 检查与生产构建。失败现场保留于 `workflows-before-disconnect-fix/`，前后复现记录为 `compression-disconnect-before.log` 和 `compression-disconnect-after.log`。

可重复执行的浏览器和 HTTP 命令见 [CONTRIBUTING](../CONTRIBUTING.md)。完整构建必须使用 `npm run build`，以生成静态模型压缩副本。备份、重启及代理配置见[运维指南](web-operations.md)。上述速度为本地固定条件下的结果；其他平台的性能分别实测和记录。
